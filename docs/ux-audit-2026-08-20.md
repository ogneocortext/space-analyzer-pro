# WinUI 3 UX Audit — Triage (2026-08-20)

**Persona:** gemma4:e2b-it-qat driven by a "Senior WinUI 3 / Fluent 2 frontend engineer" prompt
(`scripts/vision.mjs --mode winui`, plus the structured `ux_analysis` harness).
Raw per-page output: `docs/screenshots/ux-audit-2026-08-20-winui3/*.txt`.

## Verdict
No functional/layout defects across the 12 pages — every page renders, no clipping,
no broken controls, no crashes. The new persona produced **control-specific** feedback
(naming NavigationView, CommandBar, AppBarButton, ThemeResource,
`CardBackgroundFillColorDefaultBrush`, InfoBar, AutomationProperties.Name, Mica).

**Important caveat:** the app already implements a mature Fluent 2 design system in
`App.xaml` (theme-aware Light/Dark semantic brushes, spacing/typography tokens, and
`PrimaryButton` / `SecondaryButton` / `DangerButton` / `StatusBadge` styles). So a large
share of the model's "hardcoded brush / missing NavigationView / missing theme resources"
claims are **false positives** — it sees pixels, not XAML. Those were discounted below.

## High-confidence, actionable (do these)
1. **Low-contrast status text (WCAG AA).** Several status/hint `TextBlock`s used
   `Style="Type.Caption"` with inline `Opacity="0.6/0.7"`, dropping contrast below AA in
   dark mode. **Done:** added `StatusBarText` style (full opacity) and applied it to the
   live status / hint / result-readout captions across all scanned pages
   (`ScanPage`, `WorkflowsPage`, `AIAssistantPage`, `DuplicatesPage`, `AboutPage`,
   `DashboardPage`, `CleanupPage`). Build verified 0 errors / 0 warnings (VS MSBuild,
   Debug x64). Deliberately left alone: `Type.Tiny` metadata, field labels at `Opacity="0.8"`,
   and non-text opacity (separators, chart axes).
2. **Action-hierarchy convention.** Primary / secondary / destructive actions share a flat
   row with equal weight. The app already encodes the rule via `PrimaryButton` /
   `DangerButton` / `SecondaryButton`; the gap is *visual grouping*. **Done:** on
   `ScanPage` the action cluster splits primary (Start/Stop) from secondary
   (Export + format) with a `CardStrokeColorDefaultBrush` separator, status right-aligned.
   Reference implementation for the other pages.
3. **Settings: server connection status + model search.** **Done.** Added a live,
   color-coded connection indicator (dot + status text, with a progress ring while
   checking) that auto-refreshes on page load and when the AI toggle changes; the manual
   "Test Connection" button also updates it. Added a model-list **filter** (`ModelSearchText`
   → `FilteredModels`) above the installed-models chips, with a "No models match your
   filter" hint. Build verified 0 errors / 0 warnings (VS MSBuild, Debug x64).
4. **Empty-state feedback.** **Already satisfied (false positive).** Every page uses the
   established `EmptyStateCard` / `EmptyStatePanel` / `EmptyStateTitle` / `EmptyStateHint`
   pattern (icon + title + hint), not raw "No X yet" text — gemma4 mistook those cards
   for plain text. Fixed the one outlier: `LargestFilesControl`'s inline empty message now
   uses `StatusBarText` (full opacity) instead of a dimmed `Type.Caption` (WCAG AA).

## Low-confidence / discounted (do NOT chase)
- "Hardcoded brushes / not ThemeResource-driven." False positive — `App.xaml` uses
  `ThemeResource` brushes and Light/Dark dictionaries throughout.
- "Missing NavigationView." False positive — the app uses a top `NavigationView`
  (`MainWindow.xaml`); the portrait capture crops it, so the model assumed it was absent.
- "Add Mica backdrop." Aesthetic nicety, not a defect. Optional future enhancement
  (window `SystemBackdrop`), out of scope for this pass.
- Misreads of the empty initial state (fresh capture has no data) — legitimate empty
  states, not bugs.

## Convention (codified)
- Action clusters live in a `DashboardCardBorder` card.
- Primary action → `PrimaryButton` / `PrimaryCTAButton`; secondary → `SecondaryButton`;
  destructive → `DangerButton`; separate primary from secondary with a `CardStroke` divider.
- Status / live messages → `StatusBarText` (never a dimmed `Type.Caption`).
- Empty/state feedback → `InfoBar` or existing `EmptyState*` styles.
- Reference implementation: `ScanPage.xaml` action cluster.
